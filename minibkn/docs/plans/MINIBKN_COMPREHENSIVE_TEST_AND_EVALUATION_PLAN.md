# MiniBKN 全量测试与评测执行计划

> 版本：v1.0\
> 日期：2026-08-17\
> 状态：已完成（2026-08-17）\
> 上位开发计划：[MiniBKN 分步开发计划](MINIBKN_STEPWISE_DEVELOPMENT_PLAN.md)

## 1. 这轮工作要证明什么

本轮不是简单地“让测试变绿”，而是建立一套任何开发者或 AI 都能再次运行、能解释结果、能揭示边界的验收体系。最终要回答五个问题：

1. 系统换成采购、财务、人事等业务后，是否仍能发现表格结构和关系；
2. 用户用自然语言提问时，QueryPlan 能否正确理解、拆解、追问并安全执行；
3. BM25、哈希向量、BGE-M3 和混合检索各自效果如何；
4. 回答是否真的来自证据，动作是否会被权限、审批和风险规则拦住；
5. 在增量更新、并发、缓存、外部模型失败和真实界面操作下，系统是否仍可运行。

“所有测试”在本项目中的有限定义，是覆盖当前已交付功能和已声明非功能要求；尚未接入的 LightRAG 只验证预留接口与关闭状态，不虚构其检索效果。

| 层级 | 主要内容 | 是否调用外部 API | 主要产物 |
| --- | --- | --- | --- |

| QueryPlan | 改写、同义词、子问题、多跳、聚合、歧义追问、非法计划拒绝 | DeepSeek | 开发集、盲测集、对抗集原始结果 |

## 3. 数据集设计

### 3.1 数据域

- **CRM 回归集**：保留现有 500 客户、2,500 订单、6,000 明细等 9,140 条对象和 200 题，作为历史对比基线。
- **采购盲测域**：供应商、采购单、采购明细、收货、付款、审批；包含一对多、多跳、金额聚合和高风险付款动作。
- **财务盲测域**：客户、发票、收款、账户、费用报销；包含逾期、部分付款、跨表汇总和审批规则。
- **人事盲测域**：部门、员工、请假、调岗、薪资等级；包含自然键、组合键、敏感字段和权限限制。
- **质量与漂移集**：重复主键、空主键、复合键、错误类型、孤儿外键、列改名、新增列、删除记录。

所有数据使用固定随机种子生成；不得包含真实个人、企业或密钥信息。

### 3.2 问题分布

每个业务域覆盖：

- 单对象精确查询；
- 条件过滤与排序；
- 一跳和多跳关系查询；
- 数量、求和、平均值、分组等聚合；
- 同义表达、简称、口语和拼写噪声；
- 信息不足、指代不明、多个候选值等歧义；
- 越权、提示注入、要求跳过审批等对抗问题；
- 只读问题、动作模拟、需要审批的动作、必须拒绝的动作。

### 3.3 防止“背答案”

- `development`：允许看答案并用于修正提示词；
- `holdout`：固定后只运行，不据此调提示词；
- `adversarial`：专门验证歧义、安全和异常输入；
- 若根据 holdout 结果修改实现，该集合立即降级为 development，并用新随机种子生成新的 holdout。

## 4. 核心指标与验收口径

| 能力 | 指标 | 本轮门槛 |
| --- | --- | --- |
| 确定性核心 | 单元/集成/API 回归 | 100% 通过 |
| 数据发现 | 主键、组合键、外键候选 Top-1/Top-3 | Top-1 ≥ 0.85；Top-3 ≥ 0.95；孤儿关系必须给出降置信原因 |
| QueryPlan | 精确匹配、组件准确率、歧义召回、安全违规率 | holdout 精确匹配 ≥ 0.75；组件 ≥ 0.90；应追问召回 ≥ 0.90；非法可执行计划 = 0 |
| 检索 | Hit@1、Hit@5、MRR、Precision@5、Recall@5 | 如实报告四种模式；BGE-M3/Hybrid 至少一个在语义题上明显优于哈希基线 |
| Faithfulness | Ragas Faithfulness | 分层抽样集 ≥ 0.85；同时保存逐题结果和失败样例 |
| 动作安全 | 允许/审批/拒绝判定、幂等、审计 | 冻结集 100%；越权成功数 = 0 |
| 增量构建 | 图、索引和版本一致性 | 冻结场景 100%；失败构建不污染已发布版本 |
| 性能 | 搜索 p50/p95、并发错误率、缓存收益 | 不设虚假行业数字；记录同机基线，热缓存 p50 应优于冷缓存，受控并发无数据错误 |
| UI | 核心演示路径 | 关键路径全部可完成；已知限制单列 |

门槛失败不等于隐藏结果：先保留失败原始数据，再修复并生成新的结果文件；报告同时注明修复前后版本。

## 5. 真实模型与费用边界

- DeepSeek 用于 QueryPlan、歧义判断、回答生成或 Ragas 裁判；
- 硅基流动 BGE-M3 用于真实 Embedding；
- 密钥只从 `<local-path>` 或环境变量读取，不复制到日志、数据集、Markdown 或 Git；
- 先用小样本做连通性和格式冒烟，再运行完整集合；
- Ragas Faithfulness 先做分层抽样，避免 200 题多轮裁判产生无意义费用；ID 型检索指标仍跑完整 200 题；
- 每份真实评测结果记录模型名、数据版本、样本数、时间、请求数、输入/输出 Token（提供时）和失败数。

## 6. 执行顺序

1. 审计现有测试、数据、脚本和历史数字；
2. 生成多行业表格、BKN、问题、动作、异常和盲测集合；
3. 补齐确定性单元、集成、API、安全、增量和故障测试；
4. 运行 DeepSeek QueryPlan 开发集、盲测集和对抗集；
5. 运行四种检索对比、Ragas、Token、延迟与费用统计；
6. 运行大数据、缓存、并发和外部服务降级测试；
7. 运行前端自动化和真实浏览器关键路径；
8. 全量回归，归档机器可读原始结果，写技术报告、通俗报告并更新文档导航。

## 8. 已知边界

- LightRAG 仍未接入，只测试文档知识端口在禁用、超时和错误情况下不会破坏结构化主链路；
- 自动生成的业务数据能控制规模和答案，但不能等同于真实企业生产数据；
- LLM 裁判存在随机性，同一冻结抽样至少保留模型、参数和原始输出；
- “平均上下文 Token 降低 36%”只有在明确对比基线、数据集和计算公式后才能写入简历。
