# MiniBKN 阶段 D 通俗开发报告

## 1. 这一阶段解决了什么

阶段 D 的目标是把“代码能跑”变成“别人拿到项目也能理解、演示和验收”。目前从导入业务
数据、建立知识网络、检索问答，到高风险行动确认、工具执行和 Trace 回放，已经可以用一个
脚本完整走通。同时补齐了简历材料里最关键的 MCP、自动 Schema 和量化评测能力。

## 2. 一键演示与工程化

- `scripts/demo.ps1` 会建立独立演示数据库并运行完整业务链路，不污染日常数据库。
- 演示会注册两份 CSV、生成 5 个对象和 3 条关系、建立 9 个分层索引文档。
- 系统能回答哪些物料低于安全库存以及供应商是谁，并返回 BKN 文件和 CSV 行引用。
- `MAT-001` 的补货估值为 935，先暂停等待确认；批准后才执行白名单工具。
- 行动的请求、风险判断、人工批准和工具结果都能按 `trace_id` 回放。
- 增加 Dockerfile、Compose、架构说明和验收指南。Docker Desktop 当时未启动，因此容器镜像
  尚未在本机实际构建；原生 Python 验收不受影响。

## 3. 自动 Schema 与 AI 辅助

系统现在可以先发现 CSV/SQLite 的表和字段，再自动生成初始知识网络：

- 唯一的 `*_id` 字段可作为主键候选；
- 其他表中的同名 `*_id` 可推断为关系；
- 字段类型和数据源映射直接来自实际资源，生成后可以继续物化和索引；
- 可选的 OpenAI-compatible AI 只补充对象、字段和关系的业务说明，不能改变 ID、主键或字段
  映射，因此不会让“看起来合理”的模型输出破坏可执行结构。

没有 API Key 时，确定性自动生成仍可完整工作。AI 请求已用模拟服务测试，但真实外部模型
调用必须由使用者提供自己的 Key、Base URL 和 Model。

## 4. 语义检索与 MCP

默认 token-hashing 向量不需要下载模型，适合离线演示和稳定测试；项目同时实现了
Sentence Transformers 适配器，配置后会使用真实句向量。适配器采用延迟加载，未启用时不会
增加启动成本。

MCP 使用 Python SDK 2.x 原生 stdio 协议，提供三个工具：知识搜索、带引用问答、受控行动
请求。MCP 只是新入口，所有行动仍经过原来的参数校验、风险门禁和 Trace，不会绕过安全规则。
自动测试已经用 MCP Client 发现并调用工具，而不是只检查函数是否存在。

## 5. 200 条评测的真实结果

评测集由 5 个业务实体、8 种查询模板和 5 种表达包装组成，共 200 条。每条都有唯一相关文档
ID，并保存 vector、BM25、hybrid 的完整前五排名，便于复算。

| 模式 | Hit@1 / Ragas ID Context Precision@1 | Hit@3 | MRR |
| --- | ---: | ---: | ---: |
| Vector 离线基线 | 0.515 | 0.760 | 0.6442 |
| BM25 | 0.735 | 0.890 | 0.8227 |
| BM25 + Vector + RRF | 0.730 | 0.835 | 0.7934 |

这批问题包含大量物料 ID 和字段关键词，所以 BM25 比混合检索略好。混合检索相对纯向量的
Hit@1 从 0.515 提升到 0.730，增加 0.215；MRR 从 0.6442 提升到 0.7934。这个结果能说明
混合检索弥补了当前离线向量基线的不足，也说明排序策略应该按数据集调参，不能默认“混合一定
最好”。

Ragas 的无模型 `IDBasedContextPrecision` 已实际运行。Faithfulness 必须调用评审 LLM；当前
没有用户凭证，所以没有生成或伪造该数字。参考简历里的 Context Precision、Faithfulness 和
Token 降低数字都不能直接写到本项目简历中。

## 6. 简历要求的当前覆盖度

- 架构设计、结构化知识图谱、混合检索、RRF、三层上下文：已实现并有端到端证据。
- Schema 定义、字段映射、数据上传后自动生成初始图谱：已实现。
- 行动注册、参数校验、安全执行、标准结果、完整 Trace：已实现。
- MCP 原生接入：已实现并做协议级自动测试。
- 200 条问题与检索指标：已实现并保存结果。
- 真实 AI Schema 调用、真实 Sentence Transformer 模型下载、Faithfulness：代码入口已具备，
  但分别需要外部凭证或模型下载，不能冒充已完成的外部实验。

## 7. 面试时如何讲

可以把项目概括成：我没有照搬上游的 Kubernetes 微服务，而是保留 BKN 的领域和端口边界，
用 Python 模块化单体先完成可验证主链路。实时业务数据先映射为对象与关系，再将 Schema、实例
子图和行动组成三层检索上下文；检索使用 BM25、向量和 RRF，行动通过白名单和风险策略执行，
每一步都有引用或 Trace 证据。最后用 200 条固定数据集验证排序效果，并如实分析 BM25 在精确
关键词场景中更强的原因。

## 8. 当前已知边界

- 核心复现范围只接 CSV 和 SQLite，没有实现上游全部连接器、Kubernetes 和多租户平台。
- 默认向量是轻量离线基线；真实语义模型需要安装 `semantic` 扩展并首次下载模型。
- 演示工具只产生本地补货预警，不会真实下单。
- Docker 配置已完成，但需在 Docker Desktop 运行时再次执行构建验收。

这些边界是为秋招演示有意控制的范围，不影响完整主流程验收。
