# MiniBKN 性能、韧性与安全测试开发报告

> 日期：2026-08-17\
> 被测索引：9,150 文档、BGE-M3 1024 维、单应用进程

## 1. 测试覆盖

本阶段新增和执行了以下测试：

- 冷启动、缓存命中、顺序请求与 50 并发请求；
- 硅基流动 429 限流重试、503 降级、网络超时；
- Embedding 空响应、数量不符、维度不符、NaN/Infinity 防御；
- 缓存并发访问；
- API Key 缺失与错误值；
- 超长搜索/问答输入；
- QueryPlan 注入、批量动作和绕过动作安全入口；
- 动作确认、风险规则和幂等执行。

## 2. 压测发现与修复

第一次 50 并发测试中，混合检索 P95 为 49,038 ms，吞吐仅 1.02 请求/秒。所有请求虽然成功，但同步 Embedding 和纯 Python 向量计算占用了 FastAPI 事件循环，请求只能排队。

完成三项修复：

1. 索引构建与检索的阻塞计算移入工作线程；
2. BM25 与 Embedding LRU 缓存增加并发锁；
3. 9,150 × 1,024 的向量逐条 Python 点积改为 NumPy 矩阵计算，并按索引版本缓存矩阵。

## 3. 修复前后结果

| 指标 | 最初实现 | 线程卸载后 | NumPy 优化后 |
| --- | ---: | ---: | ---: |
| 混合检索顺序 P50 | 975.22 ms | 962.64 ms | **587.08 ms** |
| 50 并发 P50 | 28,463.76 ms | 17,667.52 ms | **3,479.69 ms** |
| 50 并发 P95 | 49,038.37 ms | 22,436.42 ms | **4,312.02 ms** |
| 50 并发吞吐 | 1.02 req/s | 2.18 req/s | **11.52 req/s** |
| 错误数 | 0/50 | 0/50 | **0/50** |

最终相对最初实现：并发 P95 下降约 91.2%，吞吐提升约 11.3 倍。

BM25 的 warm P50 约 31.64 ms、50 并发吞吐约 30.40 req/s。首次请求约 4.78 秒，主要用于从 SQLite 装载全部索引文档及建立 BM25 语料缓存；后续请求不再重复装载。

## 4. 韧性与安全结论

- 外部 Embedding 的临时 429/5xx 会重试；持续失败时可按配置锁存到同维度离线方案，避免索引维度混乱。
- 非法向量不会进入索引。
- API Key 使用恒定时间比较，业务 API 在配置密钥后默认受保护，健康检查仍可用。
- 搜索和问答输入限制为 4,000 字符，避免无边界提示词和资源消耗。
- QueryPlan 不能直接执行动作；动作必须走独立的风险模拟、确认和执行接口。

## 5. 仍然存在的边界

- 50 并发混合检索 P95 仍约 4.31 秒，瓶颈转为远程查询 Embedding 与单机 CPU。生产化可增加向量数据库、异步 Embedding 批处理、限流和多进程 worker。
- 当前只有网络级 API Key，没有用户级 RBAC 与字段级数据权限。对抗测试中的“导出全部薪资等级”仍可能被当成普通查询，这是已确认的 P1 安全缺口。
- 本轮是单机进程内 HTTP 压测，不等同于跨网络的生产容量测试。
