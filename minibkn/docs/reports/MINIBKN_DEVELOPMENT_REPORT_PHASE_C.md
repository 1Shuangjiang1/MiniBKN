# MiniBKN 阶段 C 开发报告（通俗版）

## 一句话结果

MiniBKN 现在不仅能告诉你“哪些物料缺货”，还可以安全地触发补货预警：需要审批的先暂停，
批准后才执行；全过程可以用 `trace_id` 回放。

## 这次补齐了哪一段

阶段 B 做到了“找到事实和相关行动”，阶段 C 做到了“安全地执行行动”。完整过程是：

```text
选中缺货物料
  -> 自动填写行动参数
  -> 计算风险
  -> 直接执行 / 等待确认 / 拒绝
  -> 只调用白名单工具
  -> 保存统一结果
  -> 记录全过程
```

## 自动绑定参数

补货预警需要 `sku`、当前库存和安全库存。调用者只需指定物料实例，系统会按照 BKN 中的绑定
规则从该实例提取参数。多传不认识的参数或缺少必填值都会立即报错，不会把不完整请求传给工具。

## 风险门禁

风险阈值写在 BKN 定义里，当前阈值为 500。系统使用：

```text
预计补货价值 = (安全库存 - 当前库存) × 单价
```

- MAT-001：`(30 - 8) × 42.5 = 935`，需要人工确认。
- MAT-003：`(25 - 4) × 18.8 = 394.8`，可以直接执行。

用户拒绝时状态变成 `denied`，工具不会被调用；一个已经结束的行动不能再次确认。

## 工具为什么是安全的

系统没有提供“执行任意 Python 代码”的入口。只有提前注册到 ToolRegistry 白名单的工具才能被
ActionType 找到。当前补货工具只是生成一条本地演示预警，不会真实采购、发邮件或访问外部服务。

## Trace 能看到什么

高价值行动的事件顺序是：

```text
action.requested
risk.evaluated
action.awaiting_confirmation
action.confirmation_approved
tool.started
tool.succeeded
```

拒绝时会出现 `action.confirmation_rejected`，工具事件不会出现。每个事件都带相同的 `trace_id`
和 execution_id，便于解释系统做过什么、为什么做、最终结果是什么。
