# MiniBKN S7 AI 辅助建模工作流产品开发报告

> 完成日期：2026-08-16\
> 前置报告：[S6 增量构建产品开发报告](MINIBKN_S6_INCREMENTAL_BUILD_DEVELOPMENT_REPORT.md)\
> 对应计划：[分步开发计划](../plans/MINIBKN_STEPWISE_DEVELOPMENT_PLAN.md)\

## 1. 与 S6 的衔接

S6 已经能够安全地把已发布网络应用到业务图和检索索引。S7 在它前面增加了一道“建模草案—逐条审核—人工发布”的流程：AI 或规则生成的内容不会直接进入在线网络，只有全部提案有明确审核结论后，产品负责人才能发布；发布完成后可直接调用 S6 的构建接口。

## 2. 用户现在可以完成什么

用户先注册并发现 CSV 或 SQLite 数据源，然后用一句自然语言创建建模会话，例如“客户订单需要创建审批动作，并默认要求人工确认”。系统会把结果拆成可独立审核的提案：

- 业务对象；
- 每个字段；
- 主键；
- 表之间的关系；
- 建议动作；
- 建议风险规则。

每条提案都带有置信度、证据、原因和审核状态。审核人可以接受、拒绝，或提交修改后的完整内容。只要仍有一条 pending，发布接口就会拒绝操作。

## 3. AI 如何参与、边界在哪里

- 没有配置 LLM 时，系统仍能根据发现的数据结构产生确定性的对象、字段、主键和关系提案；自然语言出现动作或审批意图时，会补充一个低置信度的动作与人工确认风险草案；
- 配置 OpenAI-compatible LLM 后，模型可改善业务描述并建议动作、风险；
- AI 不能修改系统发现的 id、字段、主键和关系映射；
- AI 建议的动作会被强制设为 disabled、requires_approval，并绑定 unconfigured 工具；
- AI 风险只能是 confirm 或 deny，并必须通过 S5 的安全表达式校验；
- 非法 LLM 输出会被丢弃，不能借由提案注入任意表达式或直接调用工具；
- 发布是单独的人工 API，不由 AI 自动触发。

## 4. 新增 API

```text
POST  /api/v1/modeling-sessions
GET   /api/v1/modeling-sessions
GET   /api/v1/modeling-sessions/{session_id}
PATCH /api/v1/modeling-sessions/{session_id}/proposals/{proposal_id}
POST  /api/v1/modeling-sessions/{session_id}/publish
```

典型使用顺序是：创建会话 → 展示提案 → 逐条审核 → 发布网络 → 调用 `/networks/{id}/builds`。

## 5. 数据与版本

建模会话和全部提案持久化在 SQLite 中，服务重启后仍可继续审核。发布新网络时版本为 1；若相同 network id 已存在，则发布版本自动加 1。会话发布后不可再修改，并记录最终网络版本。

## 7. 当前限制

- 本阶段不是可视化 BKN 编辑器，复杂 payload 修改需要由 S9 UI 包装；
- 自动动作建议在没有 LLM 时只提供安全占位草案，不会猜测真实企业工具参数；
- 已发布的 AI 建议动作仍是 disabled，必须在未来的工具配置/激活流程中由管理员绑定真实 MCP 工具并再次审批；
- 当前 Schema 发现仍沿用基础字段规则，组合键和统计型外键识别属于尚未实施的 S2；
- 数据漂移会通过 S6 变更集显现，但尚未把 Schema 漂移自动转换为新的建模会话。

## 8. 给 S8 的要求

文档知识模块只能通过独立端口提供证据，不得写入或绕过 S7 的结构化网络发布流程。路由层可以选择结构化、文档或混合查询，但动作与风险始终以已发布 BKN 为权威。
